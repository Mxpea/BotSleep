# 自保与随行拾取实服测试手册

**状态：待人工验收。** A 组可在 `dev-aure` `9febf5b` 加本地 starter 自保改动上执行；仅检出该提交不一定包含本地改动，开测前核对 `git status --short`。参考环境：Java 1.21.11、mc-agent-api 1.3.14。B 组是 [V1 设计](COMBAT_AND_LOOT_DESIGN.md) 的未来验收项，现版不跑、不记通过或失败。

## 1. 准备与启动

1. 用授权的专用存档和测试机器人，难度普通、生存模式。准备主世界干燥平地、开阔退路和一个能阻断射线的掩体。安排单只怪或指定组合，排除自然刷怪、其他玩家、宠物和掉落物干扰；观察者站在测试区域外。不要在正式赛事或常用存档上摆场景。
2. 停掉同一账号的旧 Harness，确认上游没有未结束动作。复制示例为测试配置；以下命令只在文件不存在时复制，路径在已忽略的 `runtime/` 下。填写测试 API 和账号，密码可通过 `MC_AGENT_PASSWORD` 提供；检查本机环境变量没有覆盖成常用账号。每个独立场景在**确认上一场正常结束后**使用单独的 `world_id`（如 `combat_a01_r1`），避免沿用撤退冷却；故障复核保留原账号和 `world_id`，不要用新标识跳过 `pending`。

```powershell
New-Item -ItemType Directory -Force runtime/combat-live | Out-Null
if (-not (Test-Path runtime/combat-live/config.yaml)) {
    Copy-Item config.example.yaml runtime/combat-live/config.yaml
}
```

编辑下列配置项，其余沿用示例；`state` 和 `logs` 相对该配置文件解析：

```yaml
agent:
  name: "CombatTestBot"  # 替换为实际测试账号
  mode: survival
survival:
  objective: starter
  world_id: combat_a01_r1
  state_dir: state
  max_runtime_seconds: 90
llm:
  enabled: false
debug:
  enable_in_game_commands: false
  flight_recorder:
    enabled: true
    output_dir: logs
  monitor:
    enabled: true
    port: 18930
```

```powershell
python -B main.py --config runtime/combat-live/config.yaml --check-config
python -B main.py --config runtime/combat-live/config.yaml
```

确认检查成功再启动；`python` 用当前工作树可用且已装依赖的 Python 替换。打开只读面板 [127.0.0.1:18930](http://127.0.0.1:18930)。先做一次无怪的登录冒烟，确认账号、心跳和日志；再将各场初始站位、装备、血量和怪物布置好，使它们出现在 Harness 的有效观察中。不要在有效观察后用传送把怪移到判定点来凑结果。

## 2. A 组：先测现有 starter 自保

通用条件：约 2 格指 BotSleep 观察到的机器人至目标距离，不以肉眼数地砖代替。正例用铁剑、无盾、20 生命/20 饥饿、同高、可见、平坦干燥站位。每例记录首个安全决策及其结果；怪在观察前就跑出条件则重摆或记「未复现」。

| 编号 | 摆场景 | 通过条件 |
| --- | --- | --- |
| A01 单怪反击 | 单只僵尸在 1.5–2.8 格内，周围无第二威胁。 | 本地 `fight_hostile`，该步站定最多挥击一次、无自动追击；`attack_sent=true` 确认已发击打才算正例触发。伤害和击杀另记；同一遭遇后续每步须重新观察，不以「整场只能打一次」判失败。 |
| A02 多怪拒打 | 保持 A01，增加第二只僵尸，确保两只同时被观察，第二只距机器人不超过 8 格。 | 不向任一僵尸出手；优先安全撤退，退路未核验时等待。若只观察到一只，不计通过。 |
| A03 弱武器拒打 | 按 A01 只给木剑（不留其它剑、斧、盾或弓弩），首个近敌观察时生命为 18–19，饥饿仍至少 8。 | 不挥击。若已恢复到满血才进入观察，重摆；它不证明低血门禁通过。 |
| A04 物种差异 | 分开两次，把僵尸换成骷髅或苦力怕，保留开阔退路。 | `starter` 不追击、不近战打这两种怪；有核验退路则撤离，否则保守等待。不要求现版自动找到掩体。 |
| A05 脱险回主线 | 先让 A02 或 A04 触发撤退；退到安全处后确认新鲜观察中威胁已解除。事先提供机器人能继续推进的主线，例如可达的采木点。 | 从新观察重新规划，出现下一项主线动作，而不是一直追怪、撤退或重放之前的动作。单有心跳或位置变化不算恢复。 |

可选：A 组通过后再开启 `llm.enabled` 重试 A01（仅在愿意产生模型调用费用时）。以 `DECISION` 判定反击来自本地安全策略，核对相关时间窗的模型槽日志：反击不能依赖一次新的模型请求；威胁发生前已有模型请求不算失败。不要因为规则模式关着模型就声称已实测模型并发场景。

## 3. B 组：V1 接入后才测

| 场景 | 未来通过条件 |
| --- | --- |
| 有缺口但无掉落 | 主线照常执行；额外扫怪、等待掉落、主动出击均为 0。 |
| 同路安全掉落 | 用任务明确需要的物品（例如骨头）摆一组有/无掉落对照；只在已核验短段上插入拾取，按库存净增更新缺口，再回主线。记录额外耗时及位移。 |
| 危险或偏离路线的掉落 | 有威胁或不能核验安全落脚时不绕路；保留缺口继续主线，不站着等。 |
| 拾取时出现威胁 | 先确认上一个动作结束再自保；威胁消失后重算主线和缺口，不按旧实体 ID 接着追。 |

## 4. 停止条件与回传

出现意外死亡、同账号双进程、重复攻击、失控追击、未知写结果或遗留 `pending`，结束该场并保留现场。正常用前台 `Ctrl+C` 结束，核对进程与上游动作均已结束后再换场；退出或 `/stop` 回执本身不是结束证据。不要为制造故障故意断开常用服务，也不要清检查点或重新发送攻击。需要复核未知写入时，先保留原配置和检查点，按 [调试与恢复指南](DEBUG_GUIDE.md) 处理。

每例只需回传：`用例｜通过/失败/未复现/未运行｜源码与上游版本｜初始血量/装备/怪物距离｜首个决策与结果｜是否恢复主线｜日志时间段`。优先截取 `DECISION`、`STEP_RESULT`、`SAFETY_INTERRUPT`、`RECOVERY_REQUIRED` 和必要的心跳/模型槽；记录 `attack_sent`、`damage_verified`、`killed`、`retreat_required`，缺字段记「未确认」。`success` 不是击杀证据。确认单挥击可结合录像或现有上游动作日志；看不到请求证据时，不声称已验证 HTTP 调用次数。不要回传 token、密码、私服地址或整个配置。
