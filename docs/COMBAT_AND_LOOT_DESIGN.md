# 自保与随行掉落收集设计

**状态：自保和已拾取骨头的利用已接入，实服待验。** `starter` 支持对符合条件的孤立僵尸单击反击；`daily` / `competition` 的现有 `craft` 目标支持用库存中的骨头制作骨粉。通用随行需求、插入拾取动作、资源保全和扩展物种策略仍是设计方向。现行战斗见 [狩猎、战斗与桶类操作](COMBAT_AND_HUNTING.md)。本设计仅针对 Minecraft 生存模式的怪物，不涉及玩家对战。

## 两种意图

| 意图 | 触发与权限 | 完成条件 |
| --- | --- | --- |
| 自保 | Harness 发现即时威胁，自动选择反击一击、撤退、找掩体或等待。不主动接敌、不追击、不为捡掉落折返。 | 威胁解除并确认当前位置安全后恢复原任务，不要求击杀。 |
| 获取掉落 | 任务确实缺物品，例如两根骨头。模型只说明缺什么，Harness 决定是否顺路拾取或做一次有界尝试。允许有限接近，接近与攻击分开调度。 | 以目标物品的实际库存净增更新缺口。挥击、伤害、击杀、看到掉落和实际拾取分别记录。 |

## 本地风险判断

- **怪量**：看当前能同时构成威胁的敌怪，不看扫描总数。结合距离、地形和射线；不能排除第二只怪参战时，不按单怪放行。
- **装备**：考虑武器档位与类型、盾、护甲、生命和饥饿。敌方装备或血量未知时，不假定对方弱；装备好不抵消围攻风险。
- **资源保全**：先分「普通」和「应保全」两档，兼顾物品价值、数量和补充成本。携带关键任务物、唯一关键工具或大量难补材料时，默认不主动开战。若直接撤退更危险，仍可在通过安全检查后反击一击来争取脱离。

不同生物采取不同避险方式：孤立僵尸进入近战范围时可考虑反击；骷髅优先切断射线、找已核验的掩体；苦力怕优先拉开距离，引信不明时不近战。史莱姆体型未知时保守处理，大个体消失后重新扫描分裂实体；烈焰人先按远程威胁避险，只走已核验的下界退路。第一阶段不做专用攻击循环。

## 随行需求

1. 缺口和主任务并存。还能采集、制作或移动就照常推进，复用已有的新鲜实体与掉落观察，不为随机刷新反复扫怪或原地等待。
2. 同路出现可安全拾取的目标物就先捡，有更安全的来源就优先采用。只有绕行成本低，且敌情、装备、落脚和退路均通过核验，才临时插入一次有界尝试。
3. 没机会就继续主线。目标跑远、敌情恶化或绕行超预算时，结束尝试并回到主线，未满足的需求保留。只有掉落成为不可替代的前置时，才做有时限的专门搜索；到期仍无进展就报告受阻，返回任务选择。

## 串行执行与恢复

本地规则决定下一步并说明原因；Harness 统一负责串行调度、核验和恢复。自保可打断取掉落，但上一个动作未确认结束前不插入新动作。`/attack(max_hits=1)` 只限制挥击次数，仍可能自动寻路贴近；两种意图的单击均复用不带移动的 `/control(hit=1, wait=True)`。一击后重新观察，再决定是否撤退，不预排固定后退。

写入结果未知时保留 `pending`，不补打、不用移动试探、不重放。脱险后重新核验环境与进度，再决定是否继续取掉落。

## V1 接口提案：同一套短步，不同的开战权限

**先验收现有自保，再实现随行拾取；主动获取敌怪掉落延后。** 不新增 HTTP 路由，不复制上游端点为模型工具，也不新增一套动作队列。以下接口是提案，不是当前可调用的工具。

| 谁调用 | 接口与输入 | 实现负责什么 |
| --- | --- | --- |
| 小模型或确定性任务 | 继续用现有目标入口（如 `run_survival_task`）。V1 由支持该物品的任务写下缺口；模型不选怪、不传坐标，也不直接驱动拾取循环。 | 给模型的摘要只说还缺什么、主线是否可继续；只有必要前置受阻时才请模型换方案。 |
| 当前任务程序 | 本地需求记录，形状示例：`{item: bone, target_count: 2}`；目标量指背包应有数量，不是再捡两件。 | 每次完整观察用库存重算缺口；记录绑定当前任务，任务结束就释放。只保留目标与恢复证据，不持久化旧实体 ID 或待重放动作。 |
| Harness 本地调度 | 从新鲜观察选一个继续主线、自保步或已注册的 `collect_drops`；不增加模型 schema。 | 自保沿用 `fight_hostile` / `retreat_from`；拾取复用 `collect_drops`，执行前复核候选位置、威胁与预算。没有安全候选就继续主线。 |

**同路的定义。** 首版只从已有完整观察取候选：目标掉落应在已经验证的短段附近，且去捡它不能逼近敌怪、进入危险地形或显著偏离主任务。若当前拿不到可验证的路线或安全落脚，就不额外走，只记自然拾取造成的库存变化。每轮至多插一个拾取步，之后重新观察并回到主任务；没有目标掉落时不新增扫描或等待。绕行格数和耗时先用靶场测量，不把估算值写成已实现阈值。

**实现前须验证的限制。** 现有 `collect_drops(entity_id, expected_item)` 核验掉落物位置、目标站位和背包增量，并用 `/move_to` 接近；8 格是技能上限，不是顺路预算，也不能保证上游实际路线安全。下一步先接「普通主线行动 → 自然拾取 → 随行缺口缩小」，只有能限制拾取路线和耗时，才允许主动插入移动。骨粉目标只消费已经进入背包的骨头，不保存主线随行需求或掉落实体。

**写入与恢复。** 复用 `SurvivalHarness` 的安全门禁、串行 `pending` 和结果验证；技能通过现有 `core/client.py` 调用上游。先确认上一动作已结束，再执行自保或拾取；停止回执不证明结束。威胁解除后以当前状态重算下一步，不恢复上一条 HTTP 写请求。写结果未知时停在原 `pending`，不清锁、不补打，也不通过移动验证。建议为未来拾取插入记录需求缺口、选择原因、额外耗时和库存增量，沿用现有只读事件渠道，不为监控另开命令入口。

末影之眼是独立的回收例外：投掷采样结束后，只追踪本次新出现且已落地的眼；先确认落点脚下支撑，再用 `collect_drops` 的同一库存后验沿核验路线拾取。旧眼、多只新眼、落点未稳、路线受阻或状态变化均不猜测、不重投、不强行拾取。

## 实施顺序与待定项

先实服验收基础自保，再接入需求记录与顺路拾取，最后评估有界主动尝试。暂不新增模型工具，不做通用追击或刷怪搜索系统。资源保全名单、绕行距离和时间、专门搜索预算，以及各怪物的放行条件，留待后续按实服证据确定。

现版可执行用例与未来验收用例分开列在 [实服测试手册](COMBAT_LIVE_TEST.md)。
